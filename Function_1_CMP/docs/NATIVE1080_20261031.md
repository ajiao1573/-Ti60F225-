# 原生 1080P 显示与识别

当前位流：`output/native1080/Ti60_Demo.bit`。已通过 Efinity Programmer 在 Ti60F225 上 JTAG 加载成功，用户确认“明显更清楚，马赛克减少”。该操作没有写入 SPI Flash；断电后需重新 JTAG 加载或自行用该位流更新启动 Flash。

## 根因和修改

旧版虽然采集、输出时序为 1920×1080，但 DDR 中实际灰度图为 848×477，HDMI 用最近邻放大，导致块状像素和细节丢失。

新版数据链路为：1920×1080 RAW8 → 去马赛克/RGB 降噪 → 原生灰度 → 全帧 Canny/定位与动态车牌 ROI 抓取，同时写入 DDR → 原生 1920×1080 HDMI。生产顶层不再实例化 `camera_full_view` 的缩小环节。归一化 ROI 为 256×96、单字符模板为 20×32 的 OCR 内部格式保持不变；定位及 ROI 取样的源图像是完整 1920×1080。

- 新增 `native_gray_capture.v`：在原生首像素接收整帧，采集中即使 DDR ready 或识别冻结请求改变，也完成已接受帧。
- DDR 原生模式：每行 1920 字节，即 120 个有效 AXI beat；按 128 beat、2048 字节行跨度存储，读出仅保留有效像素。关闭不再使用的灰度缩略平面及二进制历史写入，保留帧提交、环形实时缓存及冻结握手。
- 显示：一帧消耗 2073600 个灰度字节，1:1 显示；定位框与图像通过相同帧 ID 对齐。
- 定位/裁剪/显示：Y 坐标扩至 11 位；定位网格列扩至 8 位、行及纵向组件标签扩至 9 位，支持第 1024 行之后和右半画面，不发生回绕。
- 全帧处理：Canny 和定位均为 1920×1080；关闭整帧历史选峰 RAM。该缓存随像素数增长，直接保留会超出片上存储预算；中值、空间 Canny、局部连接及其他已配置的空间保护继续运行。模板和 OCR 误差/候选差距门槛未降低。
- STATUS 40..43 上报处理尺寸 1920×1080，定位框坐标使用该尺寸。上位机可直接解析，无需重建 EXE。

## 验证

| 检查 | 结果 |
|---|---|
| 原生 DDR 读回 | 1080 行、2073600 个像素逐字节一致，无填充泄漏，随机 AXI/消费者停顿通过 |
| 原生写入/冻结 | 2073600 个像素、1080 个完整行突发；中途冻结仍完成当前帧，释放后恢复 ready |
| 显示 | 实际 1080P30 时序下逐像素检查；正常帧完整且欠载 0，y=1040 的定位框正确 |
| 故意欠载恢复 | 原生缓存四帧检查覆盖启动、缺数据、下一帧恢复；早期独立显示测试记录 |
| 原生定位 | 右下角 x>1024、y>=1024 的候选框与独立参考算法一致 |
| 原生 ROI | x=1650、y=1040、128×32 区域取样及归一化像素、直方图和极值逐项一致 |
| 实际识别流水线 | 两帧，每帧 2073600 个输入、预览和边缘像素；84MHz/30fps 源时序；底部行保留，无缩小输入 |
| 旧版 DDR 兼容 | 原 848×477 默认模式读回回归通过 |
| Efinity | map、interface、pnr、pgm 和位流导出全部 PASS |
| 资源 | RAM190/256，DSP7/160 |
| 最终时序 | setup 最小余量 0.104ns，hold 最小余量 0.007ns；约束未放宽 |
| 实机读回 | 输入1920×1080、处理1920×1080；锁定前输入/处理均30fps，显示本帧/累计欠载均0 |
| 用户观察 | 用户明确确认画面明显更清楚、马赛克减少 |
