## 原始分辨率轮廓（2026-10-23）

显示支路采用 RGB 加权灰度 → 3×3 高斯平滑 → 阈值/ROI 分割 → 3×3 开运算 → 3×3 闭运算
→ 两像素内边界 → 红色覆盖。开运算抑制孤立噪点，闭运算修补小亮孔和短缺口。
轮廓公式为 `clean_mask AND NOT erode_5x5(clean_mask)`，颜色为 RGB888 `FF0000`。
直边向豆子内部占两格原始像素；曲线和斜线按像素网格生成两层边界，避免使用半分辨率计数掩码放大后的阶梯。
原图颜色、坐标和 DE/HS/VS 经过与窗口中心一致的行缓存，红线对应同一帧、同一位置。
在 1650 总像素/行、约 74.4 MHz 配置下，总显示延迟约七行、0.16ms，每时钟处理一个像素。
OSD 最后叠加，数字和绿色 ROI 边框优先显示。冻结后同一张图重复产生相同轮廓。

这是面向现有浅色背景、深色豆子、FPGA 实时显示条件的轮廓方案，不是所有拍摄场景的通用最优算法。
轮廓支路使用完整分辨率；原计数仍使用 640×360 连通域和面积/边界筛选，因此红色候选轮廓不等于已经通过计数筛选的目标。
面积、尺寸参数仅影响计数，不影响红线。接触目标、深阴影和大反光仍可能影响分割，需要实际图像标定阈值。
空间滤波基本定义可参考 [OpenCV 形态学说明](https://docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html)。

新增 `src/bean/bean_window.v` 和 `src/bean/bean_contour.v`，均已加入主工程与独立构建脚本。
`BEAN_CONTOUR_ENABLE=0` 可关闭轮廓；`BEAN_DEBUG_BINARY=1` 时自动旁路轮廓，以便查看原计数二值图。
`BEAN_LINE_TOTAL` 必须等于显示总行长（含消隐），本工程保持 1650；更改分辨率时必须同步调整。

验证：独立二维空间算法对照 28,672 个有效输出像素，覆盖矩形、椭圆、噪点、小孔、移动/空帧、二次复位、

## KEY1 / K1 操作及资料依据（2026-10-23 引脚纠正）

本工程的 DVP 接口和原始 LED 引脚与 VF-Ti60F225 配套工程一致。本次按该资料包的核心板 K1 修正。
上一版误用了另一套 Ti60F225_DemoBoard_v4 的 P14 配置；P14 在 VF 工程中是 LED1，不是 K1。

- VF-Ti60F225_HDK_V2.1_20251009/04_原理图&PIN TCL/Ti60_F225_Core_V1.4.pdf 第 7 页：K1 接 CSI，CSI 对应 N2/GPIOL_P_02；10k 上拉到 VCCIO1A，按下接地。
- VF 配套 06-FPGA_HDL_Basic-2023.2/02_KEY_2bit_Test/KEY_2bit_Test.peri.xml 同样把 key_data[0] 接 GPIOL_P_02，1.8V 输入。
- 当前 KEY1/K1 改为 N2/GPIOL_P_02，1.8V 输入，低有效。HDMI 工程未使用的 lcd_de_o 占用了 N2，本版移除该输出约束。
- M2/GPIOL_N_02 为核心板 K2，原 lcd_pclk_o 会从该脚输出时钟。本版也释放此闲置 LCD 时钟脚，避免驱动按键网络。
- LED0 恢复 VF 示例的 GPIOR_25/P15 摄像头帧活动指示；LED1 恢复 GPIOR_22/P14，并直接显示 freeze_request。
- 按一次 K1，消抖成功后 LED1 立即切换，不再依赖计数有效。画面在 DDR 读帧边界冻结，随后重新分析该帧并显示 HOLD。
- 再按一次 K1，LED1 熄灭，恢复实时画面和计数。长按不会重复切换。
- 如果 LED1 能切换而 HOLD 尚未出现，说明按键已收到，正在等待帧切换/计数；数量等待期间为 ----，不会锁住旧帧的数量。
- 上电即按住时，仍须等待至少一张完整摄像头帧才确认冻结，避免固定未初始化 DDR 内容。

本配置使用核心板 K1；底板 User_IO[0:1] 与核心按键共享引脚，外设不应同时驱动这些网络。
本项目只使用 HDMI 显示；释放这两个输出脚后不再提供原来未接入的 RGB LCD DE/PCLK 引脚输出。

## 摄像头方向修正

根据 OV5640 参考手册 PDF 第 37、107 页，0x3820[2:1] 控制 ISP/Sensor 垂直翻转，0x3821[2:1] 控制水平镜像。
顶层 CAMERA_FLIP 从旧表的 0x40 改为 0x46，CAMERA_MIRROR 从 0x07 改为 0x01，即两个寄存器都异或 0x06。
保留 0x3821[0] 的水平 binning 使能和其他时序位，不改变图像尺寸，也不旋转后生成的 OSD 文字。
实际安装方向仍需在开发板上确认；若更换摄像头安装方向，可单独调整这两个顶层参数。

本版本保留 OV5640 DVP → DDR3 → HDMI 通路，在显示像素时钟域增加独立计数支路。
适用条件是固定俯拍、均匀背景、照明稳定、豆子单层且相互分离。默认深色豆子、浅色背景。
统计的是当前 ROI 中的目标数量，不是传送带累计数量。接触的豆子可能被识别为一个目标，遮挡分割和跟踪尚未实现。

## 数据流程

RGB565 → 原有 RGB888 显示数据 → 灰度 → 阈值/ROI → 2×2 抽点至 640×360
→ 3×3 多数滤波 → 单帧二值 RAM → 8 邻域连通域/标签合并 → 面积和尺寸筛选 → 数量叠加。

分析模块捕获一帧后离线处理，忙时跳过新的分析帧，HDMI 连续显示。计数不累加。
所有新逻辑使用 clk_pixel，无新增时钟域，也不修改 DDR 帧调度。
关闭轮廓时视频 RGB/DE/HS/VS 延迟三个像素时钟；默认开启轮廓时一起经过上述行缓存后进入原 TMDS 编码器。
坐标直接从同一 DE 重建，避免 lcd_request 提前一个时钟产生的错位。

## 屏幕显示

- 绿色矩形为计数 ROI，默认左上角 (64,48)，右下角排他边界 (1216,672)。
- 红色两像素线为 ROI 内经平滑、开闭运算后的目标轮廓。
- 左上角 `COUNT: 0003` 为最近一次完整分析的数量，最多显示四位。
- `WAIT`：尚无完整有效结果。
- `BUSY`：正在捕获/分析下一帧，显示的数量仍是上一次结果。
- `READY`：已有有效结果，分析模块当前空闲。
- `ERROR`：标签容量不足或捕获数据不完整/乱序，数字显示为 `----`，不发布部分计数。
- 状态和数字都在显示帧边界锁存，首个结果有捕获和处理延迟。
- `HOLD`：冻结图像已分析完成，图像与数量都保持不变，直至再次按 KEY1。
- LED0 为摄像头帧活动，LED1 为按键冻结请求（不依赖计数状态）；LED 引脚已恢复为 VF 示例的 LED0=P15、LED1=P14。

## 参数与调试

参数在 example_top.v 的 BEAN_* 参数区。更改后需要重新编译并下载新位流。

| 参数 | 默认值 | 含义 |
|---|---:|---|
| BEAN_THRESHOLD | 112 | 0～255 灰度阈值 |
| BEAN_DARK_OBJECT | 1 | 1：灰度小于阈值为豆子；0：大于阈值为豆子 |
| BEAN_DEBUG_BINARY | 0 | 1：显示 ROI 阈值图；0：显示原图，两者均有数量叠加 |
| BEAN_CONTOUR_ENABLE | 1 | 原图模式叠加两像素红色轮廓 |
| BEAN_LINE_TOTAL | 1650 | 显示总行长，包含水平消隐 |
| BEAN_ROI_X0 / Y0 | 64 / 48 | 原始 1280×720 图上的左上角 |
| BEAN_ROI_X1 / Y1 | 1216 / 672 | 原始图上的右/下排他边界 |
| BEAN_MIN_AREA / MAX_AREA | 16 / 5000 | 滤波后二值图上的目标面积，单位为分析像素 |
| BEAN_MIN_WIDTH / MIN_HEIGHT | 3 / 3 | 分析图上的最小外接框尺寸 |
| BEAN_MAX_WIDTH / MAX_HEIGHT | 160 / 160 | 分析图上的最大外接框尺寸 |
| BEAN_LABEL_BITS | 10 | 最多 1023 个临时标签，含噪点及随后合并的标签 |
| BEAN_REJECT_BORDER | 1 | 排除接触 ROI 边界及边缘保护带的目标 |
| CAMERA_FLIP / CAMERA_MIRROR | 0x46 / 0x01 | 修正旧画面的 180° 倒转 |
| KEY1_DEBOUNCE_CYCLES | 1488000 | 按实际 74.4 MHz 时钟消抖约 20ms |

建议调试顺序：

1. 固定摄像头和灯光，豆子放入绿色框内并保持间隔。
2. 置 BEAN_DEBUG_BINARY=1。预期豆子为白色、背景为黑色。
3. 漏掉豆子边缘时适当提高深色目标阈值；背景大面积变白时降低阈值或改善照明。
4. 从 1、3、10 颗等人工已知数量开始验证，再调整面积和宽高上下限。
5. 出现 ERROR 时先清除二值图中的背景噪点，检查摄像头画面是否正常，再考虑增大标签容量。
6. 二值分割稳定后恢复 BEAN_DEBUG_BINARY=0，并在不同位置重复验证。

DEBUG_BINARY 显示的是滤波前阈值图，方便调节分割；实际计数使用滤波后的图。
3×3 滤波采用至少 5 个前景点的多数投票，内部是因果窗口，结果约向右下移动一个分析像素。
滤波后再次裁到 ROI，计数器还在四条 ROI 边缘设置 2 个分析像素的保守保护带，补偿滤波位移和首行/列缺失。
接触边缘或保护带的目标默认排除。完整豆子应与绿色框保持至少约 6 个原始像素的间隔。
抽点会损失细小目标和狭窄间隙；应调整拍摄距离，让豆子在分析图上占据足够像素。
面积阈值不能直接使用原始图的像素面积；仅作初估时，分析面积约为原始面积的四分之一。

连通域 RAM 只保留一行标签。每个前景点解析左、左上、上、右上标签的根，并把较大根指向较小根。
临时标签分别累积面积/外接框，扫描结束后按标签编号从大到小合并统计，因此晚出现的连接不会重复计数。
最后只统计满足面积、尺寸、边界条件的根标签。没有使用“新标签次数”直接计数。
片上 RAM 不做整块复位：二值图必须完整捕获、标签行逐项清零，新标签的父指针和统计逐项初始化。

当前配置要求图像宽高和 ROI 边界为偶数，ROI 位于图像内；分析图像总像素小于 2^20，单边小于 4096。
建议保持 LABEL_BITS=10；更大配置需要重新评估 RAM、处理时间和四位显示容量（标签位宽不得超过 13）。
修改分辨率还需要同步修改原摄像头、DDR 长度、显示时序和本模块 IMAGE_WIDTH/HEIGHT；第一版仅集成 1280×720。
