# 片上 RAM 存储布局优化

2026-10-29。发布文件：`output/bean_1080p_memory.bit`。
可靠性基线 `output/bean_1080p_reliability.bit` 已保留，用户已反馈其运行“正常”。

## 资源变化

| 项目 | 可靠性基线 | 优化版本 |
|---|---:|---:|
| RAM10 | 245 / 256（95.7%） | 197 / 256（77.0%） |
| 剩余 RAM10 | 11 | 59 |
| LUT4 | 15,620 | 16,130 |
| FF | 11,123 | 11,177 |
| 完整分辨率轮廓支路 RAM10 | 71 | 41 |
| 5×5 RGB 中值支路 RAM10 | 35 | 23 |
| RGB 平滑支路 RAM10 | 18 | 12 |

释放 48 块 RAM10，较基线减少约 19.6%。代价是增加 510 LUT4 和 54 FF。
连通域分析、DDR FIFO、DDR 帧缓存调度和可靠性保护逻辑保持原有实现。

## 原因与实现

2200 深度、16/19 位宽的推断存储器，被原映射器拆成较深的窄位宽 RAM；
部分容量没有利用。例如每条 2200×16 行缓存占 8 块 RAM10。

新增 `src/bean/bean_banked_ram.v`，将宽行缓存划分为至多 512 字的浅存储组，
使映射器使用较宽的 RAM 模式。每条 2200×16 行缓存改为 5 块，
2202×19 元数据缓存由 10 块改为 5 块。
窄位宽缓存保留原来的深存储形式，避免分组后增加小缓存碎片。

`bean_window.v` 统一使用该存储接口。接口仍是同步读取、同地址读写返回旧值、
读使能关闭时保持输出；分组选择与 RAM 读取在同一拍锁存，没有增加流水级。
分辨率、RGB565 精度、5×5 中值、平滑、形态学、两像素轮廓和计数算法均未修改。

## 验证

- 存储独立参考模型检查 16×2200、19×4403、3×4403、16×513 四种配置，
  共 59,535 个读/保持时钟，覆盖全部组边界、末尾不足一组、同地址读写和随机独立读写。
- 原生行宽 Icarus 回归对照 30,720 个有效像素，覆盖换行、彩色、随机噪声、消隐和热复位。
- 最终 1080P 参考检查连续两帧，共 4,147,200 个去噪/轮廓输出像素，
  同步和坐标逐像素一致，960×540 分析计数为 3。
- 存储、图像窗口、轮廓、视频和冻结/恢复相关的 9 项针对性回归全部通过。
  日志为 `build/memory/regression.log`；汇总为 `build/memory/summary.json`。
- Efinity 综合、接口、布局布线和位流生成通过，26 组时钟关系通过。
  全工程最小报告余量 0.026ns；像素域 setup 为 5.124ns、hold 为 0.035ns。
- CDC 报告无同步器警告。

## 构建与使用

```powershell
python sim/run_bean_tests.py
python sim/run_native_1080p.py
./sim/build_reliability.ps1 -MemoryOptimized
./sim/program_reliability.ps1 -ReleaseName bean_1080p_memory
```

最后一条命令校验源码/位流哈希并通过 JTAG 易失加载，不写启动 Flash。
完整回退位流、资源报告和前一版本的测试证据均保留。
